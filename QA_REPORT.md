## 1. Что удалось опубликовать

Прямая проверка запроса «выставить объявления по каждому разделу». Зарегистрировано 14 аккаунтов (2 из них — полностью через браузер, OTP-код `1234`).

| Раздел | Через UI | Через API | Комментарий |
|---|---|---|---|
| Легковые авто | ⚠️ обходным путём | ✅ | Штатный визард непроходим — см. B-1 |
| Мото | ✅ 2 шт. | ✅ | Марку пришлось вводить текстом — справочник пуст |

## 2. Блокеры

### B-1. Визард размещения легкового авто непроходим — тупик на шаге 5 из 21
*Размещение → Легковые. Проверено лично.*

Шаги 1–4 работают (марки 417, модели 82, годы 47, поколения 6). На **шаге 5 «Тип кузова»** проход заканчивается:

- на экране всего две кнопки: «Выберите тип кузова» и «Продолжить»;
- в выпадающем списке ровно одна надпись — **«Ничего не найдено»**;
- кнопки «Пропустить» нет — шаг 5 не входит в `CAR_OPTIONAL_STEPS = [4,9,10,14,15,17,18]`;
- «Продолжить» выводит «Выберите тип кузова» и шаг не переключается.

Причина: `GET /dicts` отдаёт пустыми массивами справочники, нужные обязательным шагам:

```
body_types         = []   → шаг 5  «Тип кузова»
fuel_types         = []   → шаг 6  «Двигатель»
drive_types        = []   → шаг 7  «Привод»
steering_positions = []   → шаг 13 «Руль»
```

Справочники `moto_*` и `commercial_*` при этом заполнены — то есть это регресс данных на бэкенде. Но фронтенд усугубляет: ни фолбэка на локальные константы, ни сообщения «справочник недоступен», ни возможности пропустить шаг.

`step-body-type.tsx:18`, `step-engine.tsx:18`, `step-drive.tsx:18`, `step-steering.tsx:15`, `validations/listing.ts:83-107`

**Ключевой сценарий автомобильного маркетплейса — продать машину — недоступен.**

### B-2. Бортжурнал: публикация через интерфейс невозможна, 422 на каждой попытке
*Бортжурнал → /logbook/create*

Форма отправляет `POST /logbook` с русским названием темы: `{"category":"ТО"}`. API ожидает слаг из списка `no_topic, automatics, advice, road_trips, breakdown, maintenance, repair, tuning, purchase, gadgets`. Ответ — 422, запись не создаётся, пользователь видит общее «Не удалось опубликовать запись».

`src/app/logbook/create/page.tsx:9-12, :31`

### B-3. «Авто прокат»: форма публикации — пустышка
*Авто прокат → «Добавить». Проверено лично.*

Заполняешь всю форму, жмёшь «Опубликовать»:

- **ноль сетевых запросов** — перехват показал пустой список;
- форма закрывается, сообщения об успехе нет;
- автомобиль **появляется первым в списке** с сегодняшней датой — пользователь уверен, что опубликовал;
- после F5 автомобиль исчезает, `GET /my/rental` возвращает `{"cars":[],"total":0}`.

Причина прямо в коде:

```js
// src/app/rental/page.tsx:77-80
const handleAddSuccess = useCallback((_car: Omit<RentalCar, "id">) => {
  // TODO: Use createRental API mutation instead
  setShowAddForm(false);
}, []);
```

Мутация `createRental` реализована в `rentalApi.ts:52`, но нигде не используется. Для сравнения — аналогичная форма гос. номеров (`plate-add-form.tsx:66`) сделана правильно и реально публикует.

## 3. Самое опасное из критичных

### C-1. На проде все загруженные фото блокируются браузером
*Проверено лично на живом сайте.*

Бэкенд возвращает ссылки на медиа по незащищённому протоколу и сырому IP: `http://72.56.126.156:8000/uploads/...`. Сайт работает по HTTPS, поэтому Chrome блокирует запрос целиком:

```
Mixed Content: The page at 'https://autotoj.tj/ad/7c6b755f-...' was loaded over HTTPS,
but requested an insecure image 'http://72.56.126.156:8000/uploads/...'
requestfailed :: mixed-content
document.images.length = 0
```

По HTTPS тот же файл недоступен вообще (соединение не устанавливается). **У любого объявления, опубликованного через приложение, на проде нет фотографий.** Работают только сидовые объявления с фото на `picsum.photos`. В выдаче `/ads` уже 3 таких объявления на первой странице.

### C-2. В бортжурнале под реальными постами висят чужие фейковые комментарии
*Проверено лично.*

Открой `/logbook/2ffd2216-fc5e-424a-ad83-17864cc4c958` — пост «Поездка из Душанбе в Хорог». Под ним:

> **Farrukh** — Отличная работа! Сколько стоили колодки? *(10 января 2026)*
> **Davron** — А проточку дисков делал? *(10 января 2026)*

Комментарии про замену тормозных колодок под постом о поездке на Памир. Настоящие комментарии не показываются никогда.

```js
// src/app/logbook/[id]/page.tsx:35
const [comments, setComments] = useState(apiComments?.comments ?? MOCK_COMMENTS);
// :40 — синхронизация сравнивает списки ПО ДЛИНЕ
if (apiComments && apiComments.comments.length !== comments.length) setComments(...)
```

У поста ровно 2 настоящих комментария, `MOCK_COMMENTS` тоже длиной 2 → `2 !== 2` ложно → мок остаётся навсегда. Та же строка 34 подставляет `MOCK_POST` («Замена тормозных колодок» автора «Алишер») — при ошибке API он остаётся насовсем, и страница несуществующего поста показывает фейковый контент вместо 404.

### C-3. Избранное на главной не работает вообще
*Проверено лично.*

Клик по сердечку на карточке: **ноль запросов**, `aria-pressed` остаётся `false` (даже визуально ничего не меняется), `GET /favorites` пуст. Причём у аккаунта с 30 объявлениями в избранном все сердечки в ленте не закрашены.

`src/app/page.tsx:85` использует локальный хук `useFavorites` (чистый `useState`, без API), а `isFavorite` вообще не пробрасывается в список — карточка всегда получает `false`. Рабочий API есть и используется на `/ad/[id]`, но на главной не подключён.

### C-4. Запчасти: все характеристики молча выбрасываются при публикации

Во всех 9 подкатегориях `handlePartsPublish` отправляет только 7 общих полей. Введённые типоразмер шин, PCD дисков, объём двигателя, сторона кузовной детали — и даже общие `brand` и `model` — теряются безвозвратно. В коде прямое признание: `// (Type-specific spec fields aren't mapped here yet.)`

`src/app/post-ad/page.tsx:130-142`

### C-5. Класс багов: приведение к числу ломает поля
*Проверено лично.*

| Поле | Код | Что происходит |
|---|---|---|
| Мото → «Такты» | `parseInt(motoForm.strokes, 10)` | Справочник отдаёт слаги `"two"`/`"four"` → `NaN` → в JSON **`null`**. Поле обязательное — форма требует выбрать то, что не сохранится |
| Владельцев «4+» | `Number(form.owners)` | `OWNERS_OPTIONS = ["1","2","3","4+"]` → `Number("4+")` = `NaN` → **`null`**. Затрагивает легковые и мото |
| Грузоподъёмность | `parseInt(loadCapacity, 10)` | Поле задумано дробным (`step="0.1" min="0.5"`), но 1.5 т → **1 т**, 0.5 т → **0** |

`src/hooks/useListingForm.ts:238, 261, 277, 289`

### C-6. Удаление объявления без подтверждения

`DELETE /my/ads/:id` уходит мгновенно по первому клику в `/my-ads`. Диалога подтверждения нет, отмены нет. При этом для «На паузу» и «Опубликовать» подтверждение есть.

`src/app/my-ads/page.tsx:71-76`

### C-7. Кнопка «Написать» мертва для гостя на всех детальных страницах

Клик не делает ничего: модалки «Требуется вход» нет, URL не меняется, запросов ноль, ошибок ноль. Причина: `useOpenChat` создаёт **свой экземпляр** `useAuth` с собственным локальным `showAuthModal`, а модалка на странице подписана на другой экземпляр.

`src/hooks/useOpenChat.ts:17`, `src/app/ad/[id]/page.tsx:345`, `AdActionBar.tsx:42`

### C-8. Мобильный таббар перекрывает ключевые кнопки

На 390×844 плавающий таббар лежит поверх:
- «Позвонить» на карточке исполнителя — единственный способ связи, `window.open` не вызывается ни разу;
- «Опубликовать» в форме аренды — тап уводит на `/post-ad` и **уничтожает заполненную форму**;
- поле ввода комментария в бортжурнале.

Конфликт `z-index`: блоки кнопок имеют `z-30`, таббар выше.

### C-9. Вкладка «На паузе» в «Моих объявлениях» всегда пуста

Страница шлёт `GET /my/ads?status=paused` — такого статуса не существует (допустимые: `active, moderation, draft, archived, rejected`). Ответ всегда пустой. Архивированное объявление исчезает из интерфейса полностью — его нет ни в одной вкладке.

`src/app/my-ads/page.tsx:21, :32`

### C-10. Правки профиля затираются при загрузке аватара

`POST /profile/avatar` инвалидирует тег `Profile`, происходит рефетч `GET /profile`, и `useEffect` перезаписывает `formData` серверными значениями. Введённый текст исчезает без предупреждения.

`src/app/profile/edit/page.tsx:49-53`

## 4. Сквозные проблемы

**Ошибки не показываются пользователю — это системная черта, а не отдельный баг.** Форма молча закрывается, кнопка молча не срабатывает, оверлей перекрывает сообщение об ошибке. Человек уверен, что действие прошло. Проявления: аккордеон-формы мото/комтранса не показывают `publishError` вообще (для легковых он рендерится, для остальных — нет); ошибки валидации запчастей отрисованы внутри свёрнутых по умолчанию секций без скролла к ним; при 500 списки показывают пустое состояние вместо ошибки.

**Моки вместо ошибок.** При недоступном API лента бортжурнала заполняется пятью захардкоженными постами несуществующих пользователей и подаёт их как настоящие записи.

**Сырые английские слаги в русском интерфейсе** *(проверено лично)*: `/parts` показывает города как `dushanbe`, `khujand`; на детальной — «Категория: **tires**»; `/logbook` — темы `maintenance`, `road_trips`, `repair`, `tuning`. При этом `/rental`, `/plates` и главная чистые — единого места перевода не существует.

**Счётчики врут** *(проверено лично)*: `/parts` показывает «Найдено 20 объявлений» при `total = 121`, `/rental` — «Найдено 20» при `total = 21`. Три страницы выводят длину текущей страницы вместо общего числа и не читают `apiData.total`. Плюс склонение везде захардкожено: «Найдено 1 номеров», «Найдено 1 автомобилей».

**Карточки — не ссылки** *(проверено лично)*: на главной ноль элементов `a[href*="/ad/"]`, карточка это `<article class="cursor-pointer">` с `onClick`. Нельзя открыть в новой вкладке, нет crawlable-ссылок для поисковиков, недоступно с клавиатуры.

**Четыре ссылки футера ведут в 404**: `/about`, `/terms`, `/privacy`, `/faq`. Страница 404 — английский дефолт Next.js.

**Осиротевшие черновики**: `publish()` создаёт черновик → грузит фото → записывает поля → отправляет, всё в одном `try` без отката. Падение загрузки фото оставляет пустой черновик навсегда, повторное нажатие плодит дубликаты. За прогон накопилось 5 таких.

**Модерация обходится** *(проверено лично)*: по контракту `submit` должен переводить в `moderation`, фактически объявления, запчасти и аренда публикуются сразу в `active` — и `submit` проходит даже без единой фотографии. Только гос. номера соблюдают контракт. Из-за этого вкладка «На модерации» всегда пуста.

**Справочник марок пуст для мото и комтранса** *(проверено лично)*: фронт шлёт `GET /brands?type=moto` (как написано в спеке §4.2) и получает `[]`; по фактическому имени параметра `?vehicle_type=moto` бэкенд отдаёт все 456 марок, то есть фильтр не работает. Данные есть — внутри `/dicts` размечены 9 мото и 15 комтранс марок. Спасает только ввод марки текстом, из-за чего объявление уходит без `brand_id` и не находится фильтром.

## 5. Что работает хорошо

Стоит отметить, потому что это не само собой разумеется:

- по 21 странице в двух вьюпортах **ни одного** `pageerror` и ни одного JS-исключения;

- XSS экранируется корректно везде, где проверяли: комментарии, сообщения чата, заголовки постов, meta-описания;
- модалка авторизации закрывается по Escape, ловушка фокуса работает;
- прод-сборка проходит чисто: `next build` → 21 статическая страница, 6 динамических, TypeScript без единой ошибки;
- чат по объявлению создаётся корректно, `POST /chats` идемпотентен, непрочитанные считаются и сбрасываются;
- у всех изображений есть `alt`;
- `/sitemap.xml` и `/robots.txt` отдаются.

## 8. Отклонено при проверке

Эти заявки агент-скептик воспроизвёл заново и опроверг — в отчёт как дефекты они не идут.

- **Бэкенд: GET /brands?type=moto|commercial возвращает пустой список, хотя марки в базе есть** — Симптом я воспроизвёл ПОЛНОСТЬЮ, но он не является дефектом этого фронтенда — корень на бэкенде, поэтому refuted=true с оговоркой (баг реальный, но неверно локализован и завышен по серьёзности).

## 9. Методика и оговорки

**Как тестировали.** 14 доменов, по агенту на домен. Каждый читал относящийся к домену код и раздел спецификации (`INTEGRATION.md`, `ADD_LISTING_SPECIFICATION.md`, `DESIGN.md`, `БОРТЖУРНАЛ.md`, `ДОБАВЛЕНИЕ_ЗАПЧАСТЕЙ.md`, `my-ads.md`, `favorites.md`, `profile.md`), составлял тест-кейсы и **реально прогонял** их скриптами Playwright на живом браузере и запросами к API. Гипотезы из чтения кода подтверждались запуском; кейс без фактического прогона помечался `skipped`, а не `pass`.

Проверяли: happy path, граничные значения, невалидный ввод, пустые состояния, состояния загрузки, ошибки сети и 500, неавторизованный доступ, перезагрузку страницы, кнопку «назад» браузера, мобильный вьюпорт 390×844, XSS-строки, эмодзи, очень длинный текст.

**Состязательная верификация.** Каждый найденный дефект отдавался отдельному агенту с заданием **опровергнуть** его, повторно воспроизведя сценарий. Основания для отклонения: не воспроизвелось; ожидаемое поведение по спеке; шум окружения (429 от параллельных агентов, dev-предупреждения Next.js). При сомнениях — склоняться к отклонению.

**Ограничения этого отчёта:**

1. **Верификацию прошли не все.** Из 284 дефектов состязательно проверены 78 (72 подтверждено, 6 отклонено) — прогон оборвался по лимиту сессии. Остальные 206 помечены ⬜: это находки одного агента с приложенным доказательством, но без независимого переподтверждения. Перед заведением задач их стоит перепроверить.
2. **Серьёзность могла быть завышена.** Там, где верификация прошла, скептики понизили серьёзность многим дефектам. У непроверенных такой коррекции не было — часть «critical» при перепроверке, вероятно, окажется «major».
3. **Возможны дубли между доменами.** Один и тот же дефект (например, неработающее избранное или mixed content) найден несколькими агентами независимо и присутствует в списке несколько раз.
4. **Часть дефектов — на стороне бэкенда,** а не этого репозитория: пустые справочники в `/dicts`, http-ссылки на медиа, обход модерации, игнорируемый фильтр `/brands`, расхождение фактических ответов API с `INTEGRATION.md`. Они включены, потому что для пользователя это неработающий продукт, но чинить их надо не здесь.
5. **Тестовые данные остались в проде.** Прогон создал ~30 объявлений, 7 гос. номеров, 4 поста бортжурнала, чаты и 14 аккаунтов с телефонами `+992900001001…1014`, `+992900000123`, `+992900009999`. Часть — намеренно мусорные (цена 0, типоразмер вне диапазона, дубликаты номеров). Их надо вычистить.

**Окружение прогона:** dev-сервер `next dev` (Turbopack) на `localhost:3000`, живой бэкенд `api.autotoj.tj`, Chromium через Playwright, вьюпорты 1440×900 и 390×844. Репозиторий при тестировании не изменялся.
